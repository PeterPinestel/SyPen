# Research-to-image handoff

Create a compact project brief before visual work. Use the research plugin's fact ledger and semantic map when available. The image skill should not treat keyword volume, competitor copy, or hypothetical benefits as product proof.

## Minimum intake

- Marketplace/language; product and offer scope (one variant, family, collection); requested deliverable and whether the job is from scratch or adaptation.
- Product truth: seller-confirmed attributes, source links/files, included items, customization details, dimensions that affect depiction, approved claims, and unresolved facts.
- Actual-product references: filename and which view/part each image establishes. Identify sample engravings and placeholder supplier marks separately.
- Brand assets: logo, palette, typography, and any approved visual direction. Missing brand guidance should not trigger invented logos.
- Optional adaptation sources: old image stack and desired scene elements. These never supersede the new product reference.
- Optional inspiration library: image locations and annotated pattern candidates. These never establish product facts.
- A+ availability: Basic, Premium, Brand Story, and the Seller Central module templates actually available. If unknown, prepare a modular concept and mark implementation choices pending.
- Delivery destination and desired editable format.

## Plan each asset

| Field | Record |
| --- | --- |
| Job | One distinct question or buying decision this asset addresses |
| Fact/claim | Wording and source in the product fact ledger |
| Visual proof | What the image must show to support the wording |
| Product | Exact variant, count, and visible reference details |
| Layout | Composition, hierarchy, text zones, mobile crop |
| Inspiration | One or two structural patterns and why they fit |
| QA risk | Most likely product, claim, text, or crop error |

For A+, add the selected module type, native versus embedded text, page position, transition from the preceding module, desktop/mobile behavior, and any cross-variant relationship. Do not invent a module's exact dimensions or field budget; check the current Seller Central template.

## Final manifest

List each file, dimensions, role, fact sources, product reference, product-fidelity result, copy result, mobile result, and unresolved issue. Mark `concept`, `needs review`, or `approved for handoff` honestly. An approved handoff means QA passed; it does not mean Amazon has accepted or published it.
